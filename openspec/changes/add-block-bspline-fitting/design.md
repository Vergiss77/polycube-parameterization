# Design

## Context

动机见 proposal.md，行为要求见 `specs/polycube-block-decomposition` 和 `specs/bspline-volume-fitting`。

现有代码中，本 change 直接用到的部分：

- **polycube 网格**：流水线在归一化、已旋转到轴对齐的坐标系中得到 polycube 四面体网格。简化启用时是 `SimplifiedPolycube::map.X`，关闭时是 `FinalMapResult::X`。每个面片的节点在轴向上的坐标等于其高度，误差 ≤ 1e-9 × 对角线。
- **高度组**：`SimplifyResult` 给出 `group_of_patch` 和 `patch_height`。关闭简化时，可用 `build_height_graph` 的归组规则（同轴、高度相等，1e-12 相对容差）从 `FinalMapResult::heights` 得到。
- **原模型网格**：原模型的四面体网格 `tets.X` 用输入单位，与 polycube 网格共用同一套四面体 `T` 和边界三角形 `B`。
- **点定位**：`TetLocator`（AABB）可以定位点所在的四面体，并给出重心坐标插值后的映射。
- **输出**：`io/vtu` 目前只写四面体和三角形网格，`io` 中没有 XML 写出。
- **求解器**：Eigen 3.4 自带稀疏 LDLᵀ 和 CG。项目约束不用 SuiteSparse。

## Goals / Non-Goals

**Goals:**
- 分块和拟合都只依赖"轴对齐 polycube 四面体网格 + 高度组 + 原模型四面体网格"，与简化开没开无关。
- 块间 C0 由构造保证（共享控制点），而不是靠拟合"凑"出来。
- 全流程确定性：同一平台上输出逐位一致。

**Non-Goals:**
- 不优化块的数量和形状（不合并块、不平移切割面）。
- 不修复负 Jacobian，只如实报告。
- 不链接 G+Smo，也不在 CI 中用 G+Smo 读取输出。

## Decisions

### D1 全局网格分块，而非局部延伸切割面

每个轴的切割坐标取该轴所有高度组的高度。三个轴的切割坐标组成一个全局网格，网格格子中位于 polycube 内部的就是块。

- **为什么成立**：polycube 的每个面片都位于某个高度组的平面上，面片边界（棱线）都沿某个轴，并且位于相邻面片的高度上。所以 polycube 恰好是若干网格格子的并集。
- **好处**：
  - 相邻格子天然面对面完全重合，没有 T 型连接；
  - 块编号可以直接用 (ix, iy, iz) 区间编号。
- **备选**：只把每个面片所在平面在实体内部延伸到碰到表面为止（Chen 的局部切割）。
  - 块更少，但会产生 T 型连接；
  - 要做 C0 拼接，就得再把切割传播出去以消除 T 型连接，实现复杂得多。
- **代价**：切割面贯穿整个模型，块数可能明显增多。
  - 上界是网格格子总数：TAILSITTER 简化后切割面为 23/21/5，最多 22×20×4 = 1760 个格子；CLEVIS 最多 5×5×4 = 100 个；I-SPAR 最多 1×3×3 = 9 个。
  - 实际块数在任务 6.2 中实测并记录。合并块留到后续 change。

### D2 格子内外判定与面分类

- **内外判定**：对每个格子中心计算它相对 polycube 边界三角形的广义绕数（libigl `winding_number`），大于 0.5 即为块。格子中心离表面至少半个最短区间，不会落在边界上。不用 `TetLocator`，因为翻转四面体处的重叠或空洞可能让定位结果不可靠。
- **面分类**：
  - 格子的某个面另一侧的格子也是块：该面是内部面，相邻关系由网格位置直接得到，自然对称；
  - 另一侧不是块（或在网格外）：该面是边界面。在面中心附近用 AABB 找最近的边界三角形，取其面片编号，并检查该面片的轴与面法向一致。不一致时报错，说明违反了 D1 的前提。
- **体积检查**：块体积之和与 polycube 四面体网格的总有向体积比较，相对误差 ≤ 1e-9（spec 要求）。

### D3 参数化与目标映射

- **参数化**：块 [x₀,x₁]×[y₀,y₁]×[z₀,z₁] 上，参数 (u,v,w) 由 x = x₀ + u(x₁ − x₀) 等仿射给出，三个方向都与 polycube 的 +x、+y、+z 一致。全局旋转是正常旋转，所以映射保持定向时 Jacobian 为正。
- **目标映射**：用 `TetLocator(polycube X, T).map(q, tets.X)`，直接得到输入单位、输入坐标系中的位置。不必再处理归一化与旋转的逆变换。
- **边界采样点**：位于块面上的采样点可能因舍入落在 polycube 外。定位失败时，把它向块中心收缩 1e-10 × 对角线再定位（只对失败的点收缩，其余点不引入偏移）；仍失败时，取重心距离最近的四面体，用其（可能为负的）重心坐标外推。这类点计数后写入统计报告（spec: Unlocated sample points）。

### D4 共享控制点的样条空间

- **单元数**：每个轴的每个区间 k 的单元数为 n_k = max(1, round(L_k / h))，其中 h = element_size × polycube 包围盒对角线（归一化坐标）。次数为 p（默认 3）。
- **节点向量**：块在该方向上用开放均匀节点向量，有 n_k 个单元，控制点数为 n_k + p。
- **全局控制点格**：沿每个轴，区间 k 的控制点在全局一维编号中从偏移 O_k 开始，且 O_{k+1} = O_k + n_k + p − 1。相邻区间共用端点那一层控制点。
  - 块的局部控制点 (i, j, l) 映射到全局格点 (O^x + i, O^y + j, O^z + l)；
  - 只有被至少一个块引用的格点才成为未知量，按全局格点的字典序编号。
- **为什么 C0 成立**：开放节点向量下，块的面只由面上那一层控制点决定。两个块共享同一层格点，面上的样条完全相同，C0 偏差为舍入量级。只共享棱或角点的块同样自动一致。
- **备选**：各块独立拟合后再对公共面上的控制点取平均。拟合误差和连续性互相牵制，效果不如直接共享未知量。

### D5 采样与全局最小二乘

- **拟合采样**：每块每个方向取 m = n·s + 1 个均匀参数值（s = samples_per_element，默认 4，包含两端），得到张量积采样点。位于模型表面的块面上的采样点记为表面采样点，用于分项误差。
- **方程组**：未知量为 N 个控制点，三个坐标分量共用同一个系数矩阵 A（每行最多 (p+1)³ 个非零元）。求解

  (AᵀA + λ·κ·S) c = Aᵀ b

  - S 是每个块内控制网沿三个方向二阶差分的平方和，表示控制网光顺；
  - κ = tr(AᵀA) / tr(S)，使 λ 无量纲（默认 1e-6）；
  - S 让采样稀疏处方程组仍然正定。
- **求解器**：Eigen `SimplicialLDLT`（AMD 排序），三个右端项一次分解。
  - 规模估计：TAILSITTER 几百个块，每块 4–6³ 个控制点，去重后约数万个未知量，LDLᵀ 的内存和时间都可以接受；
  - 若分解失败（数值上不正定），报错并给出 λ 的建议，不悄悄换求解器。
- **确定性**：组装按块编号和采样点顺序串行进行，三元组按固定顺序生成，不用多线程归约。

### D6 误差与 Jacobian 评估

- **误差**：拟合误差直接在拟合采样点上计算。到原模型表面的距离用边界块面上的评估点，对 `tets.X`、`B` 构成的表面调用 libigl `point_mesh_squared_distance`。所有误差都除以输入包围盒对角线。
- **Jacobian**：在每块每个方向上的 n·4 + 1 个评估点上（包含单元边界，固定值，不作为参数），计算 J = ∂(x,y,z)/∂(u,v,w) 与缩放 Jacobian det J / (|J_u|·|J_v|·|J_w|)，统计最小值、平均值、非正点数与比例，以及含非正点的块数。
- **C0 偏差**：对每个内部面，在两侧块的面采样点上分别求值，取最大差。由 D4 的构造，这只是对实现的自检，预期为舍入量级。

### D7 G+Smo XML 格式

手写 XML，不引入 XML 库。结构：

```xml
<xml>
  <Geometry type="TensorBSpline3" id="0">
    <Basis type="TensorBSplineBasis3">
      <Basis type="BSplineBasis" index="0"><KnotVector degree="3">0 0 0 0 0.5 1 1 1 1</KnotVector></Basis>
      <Basis type="BSplineBasis" index="1">...</Basis>
      <Basis type="BSplineBasis" index="2">...</Basis>
    </Basis>
    <coefs geoDim="3">x y z
      ...</coefs>   <!-- u 最快、w 最慢 -->
  </Geometry>
  ...
  <MultiPatch parDim="3" id="N">
    <patches type="id_range">0 N-1</patches>
    <interfaces>...</interfaces>
    <boundary>...</boundary>
  </MultiPatch>
</xml>
```

- **面编号**：用 G+Smo 的 boxSide 约定：1 = u=0（west），2 = u=1（east），3 = v=0（south），4 = v=1（north），5 = w=0（front），6 = w=1（back）。
- **接口**：所有块的参数方向都与全局轴一致，所以每个接口的方向映射都是恒等，方向都为正。接口行中方向映射与方向符号的具体写法，在实现任务中对照 G+Smo 源码中读取接口的代码确定，并在 README 中说明。
- **数值精度**：控制点和节点用 17 位有效数字写出，保证读回逐位一致（spec 要求相对误差 ≤ 1e-15）。
- **读回**：只为测试实现一个解析本项目自己输出的最小读取器，不追求通用 XML 解析。

### D8 VTU 六面体采样网格

- 扩展 `io/vtu`：支持六面体单元（VTK_HEXAHEDRON = 12）和逐点标量字段，复用现有的写出代码。
- 采样网格：每块按 D6 的评估网格生成 (n·4)³ 个六面体，点不在块之间去重，便于按块查看。
- 字段：逐单元 `block`，逐点 `scaled_jacobian`。

### D9 流水线、参数与模块划分

- **阶段**：`Stage::Blocks = 5`、`Stage::Fit = 6`，`--until` 默认 `fit`。
- **输出**：
  - 分块阶段写 `06_blocks.json`、`06_blocks_polycube.vtu`、`06_blocks_input.vtu`；
  - 拟合阶段写 `07_bspline.xml`、`07_bspline_samples.vtu`；
  - 统计字段为 `stats["blocks"]` 和 `stats["fit"]`。
- **参数**：`FitParams{degree = 3, element_size = 0.05, samples_per_element = 4, smoothing = 1e-6}`，以 `fit` 段写入 `params.json`。未知键和非法值报错，沿用其他参数段的做法。
- **命令行**：`pcp_cli` 新增 `--degree`、`--element-size`。其余参数通过参数文件设置。
- **模块**：
  - `src/pcp/blocks/block_layout.{h,cpp}`：D1、D2；
  - `src/pcp/blocks/bspline.{h,cpp}`：节点向量、基函数及其导数（Cox–de Boor）、张量积求值；
  - `src/pcp/blocks/spline_fit.{h,cpp}`：D3–D6；
  - `src/pcp/io/gismo_xml.{h,cpp}`：D7。
- **调试与实验**：沿用 `test_profile.cpp` 的做法，增加一个默认跳过的用例，从已有输出目录读取 polycube 网格和分组后只跑分块与拟合，避免每次重跑前面约 20 分钟的阶段。

## Risks / Trade-offs

- **[切割面贯穿全模型，块又多又薄]** TAILSITTER 的 0.5 mm 台阶等细小区间会被延伸到整个模型，形成很薄的块。
  → 薄区间只分 1 个单元，光顺项保证方程组正定；块数和最薄块的尺寸写进统计和实验记录，为后续"合并块"提供依据。
- **[负 Jacobian]** 映射本身的畸变、TAILSITTER 残留的翻转单元，以及最小二乘的振荡，都可能产生非正 Jacobian。
  → 本 change 只报告，spec 只要求 I-SPAR 全为正。下一个 change 做控制点优化。
- **[TAILSITTER 拟合误差可能超过 5e-3]** 阈值在实现前无法实测确定。
  → 任务 6.2 实测，超标时先分析原因（单元尺寸、薄块、翻转附近的采样点），需要放宽验收时先与用户确认，并记录为已知限制。
- **[G+Smo 接口写法细节]** 方向映射的字段顺序如果写错，G+Smo 读入后接口会错配，但本项目测试发现不了。
  → 实现时对照 G+Smo 源码确定写法；本机或 CI 上没有 G+Smo，在 README 中给出用 G+Smo 读取的验证方法，由用户可选地手动验证。
- **[稀疏 LDLᵀ 规模]** 如果块数远超估计，分解的内存和时间可能偏大。
  → 统计报告给出未知量数和求解耗时；必要时改为带预条件的 CG（同样是 Eigen 自带）。这是实现层面的替换，不改变 spec。
- **[边界采样点定位失败]** 采样点刚好落在边界上时可能定位不到。
  → D3 先收缩再找最近四面体，计数写入统计报告，测试中检查其比例很小。

## Migration Plan

- 新增阶段在 `simplify` 之后，默认运行到 `fit`。已有输出文件（`00_` ~ `05_`）的内容和顶层统计字段都不变。
- 想得到旧行为（不分块、不拟合），用 `--until simplify` 即可。
- 模型测试的总时长会增加，增量是分块与拟合的耗时，预计为分钟级。README 中的 CI 时长在任务 6.4 中更新。

## Open Questions

- 默认单元尺寸 0.05 和光顺权重 1e-6 是初值，在任务 6.3 中对比几组取值后确定。只改默认值，不影响 spec 和任务划分。
