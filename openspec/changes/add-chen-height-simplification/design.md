# Design

## Context

动机见 proposal.md。与本设计直接相关的现状：

- `build_patch_graph` 已经给出面片的轴、方向、高度，以及每条棱线的 `axis`、`lower_patch`、`upper_patch`。当时的注释就写明是为 Chen 的有向边预留的。现有模型上所有棱线都有两端面片（CLEVIS 60/60，TAILSITTER 168/168）。
- `compute_final_map` 内部按轴用并查集把"共享顶点的同轴面片"合成一个高度变量（高度组）。它有 `heights_fixed` 模式，把每个高度组固定为给定高度（组内按面积加权平均）后只解自由节点。这个模式目前还没被流水线用过。
- 最终映射解出的高度几乎互不相等。按 4 位小数统计：
  - CLEVIS 24 个面片对应 24 个高度（X 10、Y 6、Z 8）；
  - TAILSITTER 59 个面片对应 59 个高度（X 26、Y 27、Z 6）。
- 当前流水线的阶段为 validate → tet → l1 → structure，structure 阶段输出 `03_*` 和 `04_polycube.*`。

## Goals / Non-Goals

**Goals:**
- 忠实实现 Chen §5.1–§5.4 的贪心有向图简化和 §5.5.1 的按新高度重变形。
- 简化算法与网格解耦：输入只是"高度组 + 有向边 + 静止长度"，可以用手工构造的小图做单元测试。
- 不引入新依赖，Windows 和 macOS 行为一致，同一平台上结果逐位确定。

**Non-Goals:**
- 不保证简化后体映射可逆（Chen 的约束只是必要条件），只做检测和报告，见风险一节。
- 不做 Chen 用来加速的堆。图很小，每步全量重算代价即可。
- 不改变 `04_polycube.*` 和现有统计字段的含义：它们仍表示简化前的结果，简化结果用新字段和新文件给出。

## Decisions

### D1 简化输入：与网格无关的高度图

新模块 `pcp/structure/height_simplify.{h,cpp}`，核心数据结构：

```
HeightGraph {
  groups: [{axis, height, patches[]}]          // 初始高度组
  edges:  [{from_group, to_group, rest_len}]   // from 低 → to 高，同轴
}
SimplifyResult { group_of_patch, heights (per patch), merges [{a, b, height, cost}], ... }
simplify_heights(HeightGraph, SimplifyParams) -> SimplifyResult
```

`build_height_graph(PatchGraph, heights)` 负责从流水线数据构造：

- **初始高度组**：同轴、且最终映射高度逐位相等的面片归为一组。这与最终映射的并查集分组一致，因为同组面片共用一个变量，高度必然逐位相等。
- **有向边**：每条 `lower_patch`、`upper_patch` 都有效的棱线生成一条边。缺少端点的棱线不产生约束，只计数并在日志中报告。
- **静止长度**：两端组的高度差 r̄。用高度差而不用棱线的折线长度，因为最终映射是严格 polycube，两者相等，而高度差没有离散误差。

### D1b 间隔边（对 Chen 的扩展）

实现时发现 Chen 的棱线约束不足以防止压扁。在 U 形算例（底板两端各一个凸台）中，底板的底面和顶面之间没有棱线相连，算法把两者对齐到同一高度，板厚变为 0，重新映射后出现 33 个翻转四面体。经用户确认，增加间隔边：

- **取样**：在简化前的 polycube（最终映射结果，严格轴对齐）上，从每个边界三角形的重心沿 ±(其轴向) 各打一条射线，用 libigl 的 AABB 求交，跳过不属于该轴的三角形和 t ≈ 0 的命中。
- **加边**：第一个命中的三角形若属于同轴、反向的面片 q，就在 p、q 之间按高度加一条"低 → 高"的边。向内的射线穿过实体，约束板厚；向外的射线穿过空隙，约束间隙。棱线约束可以看作宽度为零时的特例。
- **去重**：每个（低面片, 高面片）只保留一条边，静止长度取高度差。
- **地位**：间隔边与棱线边完全同等，参与可达性、拉伸上限和 Σd 代价。

### D1c 宽度边（对 Chen 的扩展）

在 CLEVIS 上发现，间隔边仍不够。底板端面（+X，x = 47.5）和耳片外侧面（+X，x = 29.4）之间既没有棱线相连，也不沿 X 正对，只被底板顶面上的一条窄带隔开。贪心把两者对齐到 31.4，窄带几乎消失，重新映射后有 1129 个翻转。经用户确认，增加宽度边：

- **取样**：对每个面片 P（轴 b）的每个三角形重心，在 P 的平面内沿两条面内轴 a 的 ± 方向，与 P 的边界边（P 与其他面片之间的边）求交。
- **加边**：两侧最先碰到的边界边若都属于轴 a 的面片 Q1（低侧）、Q2（高侧），就加边 Q1 → Q2。每对面片只加一条边。
- **地位**：与棱线边、间隔边同等。棱线约束其实是宽度边的退化情形（窄带宽度方向上的一维版本）。

验证结果：CLEVIS 的切割面数为 24 → 17，只剩高度几乎相同的面在合并，翻转数与简化前相同。

### D1d 翻转回退

TAILSITTER 加了宽度边后仍有问题。贪心到后段（代价 ≥ 0.6），会把错开的反向同轴面（如 +X 与 −X）对齐，不违反任何次序约束，但薄结构的体映射被扭坏：前 19 次合并（59 → 40）的翻转数与简化前持平，全部 27 次合并则有 2519 个翻转。经用户确认，加回退：

- **基准**：用简化前的高度做一次固定高度映射（不解缠），记下翻转数 n0。
- **全量检查**：对全部 M 次合并的高度做一次映射；翻转数 ≤ n0 就全部保留。
- **二分**：否则对前缀长度二分（假设单调，属于启发式），找满足翻转数 ≤ n0 的最长前缀 k。
- **最终映射**：用前缀 k 的高度做最终映射，并做解缠。
- **记录**：输出贪心与保留的合并数、n0 和 n(k)。
- **代价**：额外 2 + ⌈log₂M⌉ 次不解缠的映射（TAILSITTER 每次约 15 s）。
- **实测局限**：TAILSITTER 上翻转数并不随前缀长度单调变化。贪心给出 27 次合并，二分只保留前 10 次（59 → 49），而前 19 次（59 → 40）其实也满足判据。这样做偏保守，但能保证不变坏。改进方向（例如逐次接受或跳过）会显著增加映射次数，留作后续。

替代方案是给单次合并代价设上限。没有采用，因为阈值是经验值，也不保证不翻转。

### D1e 解缠计算量上限

翻转很多时，现有的局部解缠（最多 6 轮，每轮至多 5000 次梯度步，每步遍历整个区域）可以跑上一小时。给 `FinalMapParams` 增加 `untangle_budget`，即全部轮次累计的"四面体能量求值次数"上限，默认 1e9（2e8 时 TAILSITTER 原最终映射的解缠被截断，翻转从 1 变为 3）。超过上限就停止解缠，并按实际剩余的翻转数报告。按计数而不是按时间截断，保持结果确定。

只在三角形重心取样，可能漏掉投影重叠很小的面片对。每对面片会从两侧各打一次射线，实际风险很小；漏掉的情况仍会体现在重新映射的翻转数里。

替代方案是直接在 `PatchGraph` 上操作。没有采用，因为那样单元测试必须构造网格，而 Chen 图 4 这样的手工算例就没法直接写出来。

### D2 候选对：同轴且不可达

每个轴各自是一个 DAG，因为棱线两端面片的轴就是棱线方向，所以边只连接同轴的组。每次合并后，用位集重算该轴的传递闭包：顶点数 ≤ 几十，边 ≤ 几百，开销可以忽略。候选对是同轴、且 i 不可达 j、j 也不可达 i 的组对。

合并两个互不可达的顶点不会产生环，因此 DAG 性质保持不变，所有棱线的"低 < 高"在合并后依然可以满足。这正是 Chen 的非退化论证。

### D3 合并代价：Σd 的增量，一维凸优化

d(l) = r̄/r + r/r̄。合并 (i, j) 到高度 h 时，只有与 i、j 相连的边长度会变。

- **代价**：取 ΔD = Σ_{l∈T(i)∪T(j)} d(l, h) − Σ_{l∈T(i)∪T(j)} d(l, 当前)，即目标函数式 (7) 的精确增量。Chen 式 (8) 只取第一项，会偏向度数小的顶点，而用增量做贪心才与式 (7) 一致。这是唯一有意偏离论文的地方，记入实验文档。
- **可行域**：每条相关边要求 r ∈ [r̄/s, r̄·s]，换算成 h 的一个闭区间，各区间求交得到 [a, b]。交集为空，这一对就不可行。由于 r ≥ r̄/s > 0，"低 < 高"自动成立。
- **求解**：每个 d 是长度 r 的凸函数，r 是 h 的仿射函数，所以总和在 [a, b] 上是凸的。对导数做定次数（100 次）二分求最小点，不用迭代容差判停，保证确定性。论文用的 Ipopt 对一维问题没有必要。

**参数化**：最大畸变 D 改用最大拉伸比 s 表示（D = s + 1/s），更直观；默认 s = 2。

### D4 贪心循环与确定性

每步枚举全部候选对，计算 (ΔD, h*)，选 ΔD 最小的一对。代价相同时按 (较小组号, 较大组号) 排序。合并后的组取较小的组号，高度设为 h*；其他组的高度不动。

循环直到没有可行候选。每次合并记录 (a, b, h*, ΔD)。复杂度 O(merges · n² · deg)，现有模型上是毫秒级。

### D5 按新高度重新映射

调用 `compute_final_map(rest, X_prev, T, B, graph, new_heights, {heights_fixed = true, 其余同 final_map 参数})`：

- `rest` 是原始（归一化后的）四面体网格，`X_prev` 是简化前的最终映射结果；
- 继续使用式 (17) 的 Laplacian 初值和解缠。

这正是 Chen 式 (12)：在约束 C(Ũ) = 0 下最小化 Eδ(Ũ)。合并后，被合并的组在最终映射内部仍是不同的变量，只是被固定为同一个值，因此不需要改 `final_map`。

### D6 流水线接入

- **阶段**：新增 `Stage::Simplify = 4`，`parse_stage` 接受 `simplify`，`PipelineOptions::until` 的默认值改为 `Simplify`。
- **参数**：新增 `SimplifyParams { enabled = true, max_stretch = 2.0 }`，作为 `PipelineParams.simplify`，出现在 `params.json` 中，未知键照常报错。
- **命令行**：`--no-simplify`、`--max-stretch <s>`。
- **输出**：
  - `05_simplify.json`：每个面片的轴、简化前后高度、所属组，以及合并记录和每轴切割面数；
  - `05_polycube_simplified.tmsh`；
  - `05_polycube_simplified.vtu`，带 `arap` 和 `inverted` 字段。
- **统计**：`stats.json` 新增 `simplify` 字段，含：
  - 简化前后每轴和总切割面数、合并次数；
  - `max_stretch` 和实测长度比的最小、最大值；
  - 简化后 polycube 的 `arap_mean`、`arap_max`、`inverted_tets`、`inverted_before_untangle`、`max_planarity_error_rel`；
  - 耗时。

  现有顶层字段不变，仍表示 `04` 的结果，因此上一个 change 的测试和文档不受影响。
- **关闭简化时**（`enabled = false`）：跳过该阶段，不写 `05_*`，`stats.json` 中 `simplify` 为 `{"enabled": false}`。

### D7 测试策略

- **单元测试**（与网格无关）：
  - U 形 polycube：底板的底面和顶面、两个凸台的内侧面都不被合并，只有两个顶面合并，重新映射后无翻转；
  - 手工图：链状 A → B → C 不合并 A、C；两个孤立组会合并；不同轴的组不合并；
  - 单对合并高度与解析最优解一致：两条边 r̄1、r̄2 时可以写出闭式解；
  - 拉伸上限：s 很小时没有合并，s 增大时合并数不减；
  - 确定性：重复运行结果相同；
  - 一个小立方体组合体（L 形）经过完整的 `build_height_graph` → 简化 → 重映射，检查平面度和翻转数。
- **模型测试**：现有 `model_*` 用例因为默认开启简化，会自动覆盖新阶段，在其中增加 `simplify` 字段的检查。
  - TAILSITTER 的拉伸比对比不再完整跑两遍：在 `model_tailsitter` 运行完后，读出 `03_patch_graph.json` 构造高度图，直接分别以 s = 1.5 和 s = 3 调用 `simplify_heights` 比较切割面数，只增加毫秒级开销。
  - 为此 `03_patch_graph.json` 需要包含逐位精确的高度和棱线端点，目前已经满足。

## Risks / Trade-offs

- [Chen 的棱线约束只是非退化的必要条件（U 形算例已证实会压扁底板）] → 已通过 D1b 的间隔边解决（经用户确认）。剩余风险是重心取样漏掉的面片对，由重新映射的翻转数兜底，`05_simplify.json` 的合并记录可以定位是哪次合并引起的。
- [贪心不保证全局最少的切割面数] → 与论文一致。合并记录和每步代价都写入输出，方便之后比较其他策略。
- [TAILSITTER 的台阶仍然存在，简化后会留下薄层] → 不在本 change 范围内（proposal 已说明），实验文档会记录简化前后的切割面数，作为是否另开"改拓扑去台阶" change 的依据。
- [再跑一次最终映射，增加 TAILSITTER 的运行时间（约 2–3 分钟）和模型测试时间] → 可以接受；CI 的模型测试本来就是手动触发。
- [默认 s = 2 是经验值] → 实施时在三个模型上对比 s = 1.5、2、3 的切割面数和畸变，必要时调整默认值，结果写入 `docs/experiments.md`。

## Migration Plan

- 默认开启简化后，`pcp_cli` 的完整运行会多出 `05_*` 文件和 `simplify` 统计字段，已有的文件和字段含义不变。
- 需要旧行为时，用 `--no-simplify` 或 `--until structure`。
